Quick Example

From a subscription URL to a running proxy — one command.

shell
# Subscribe once, then run the engine headless
kiss run --subscribe https://example.com/sub --port 7897

# List your subscriptions — offline, straight from the local db
kiss subs

# Refresh or delete one subscription
kiss sub refresh https://example.com/sub

What's inside

Four things a good proxy platform needs — each first-class.

📡Subscription management

Import by URL, refresh on a schedule, and track usage and expiry per subscription. Settings, subscriptions and stats live in a local database.

kiss --subscribe https://example.com/sub

🔀Multi-engine routing

One config layer over sing-box, xray-core and mihomo, so your subscriptions keep working no matter the upstream format.

kiss run --port 7897

🛡️TUN & mixed inbound

Transparent system-wide proxy with TUN, or a plain HTTP/SOCKS mixed inbound — or both at the same time.

kiss run --tun --port 7897

🖥️Cross-platform UI

The same product on desktop and mobile: GPU-rendered native views, no WebView, no JavaScript runtime.

zig build run

Why KISS

  • One binary, four faces. Tray, window, CLI and service are the same file — pick the interface, not a different program.
  • Local-first. Settings, subscriptions and statistics live in a local database.
  • Native all the way down. Written in Zig, rendered on the GPU — no WebView, no JavaScript runtime.
  • MIT licensed. Free to use, inspect and modify.

Installation

Binaries and one-line installers are in preparation.

Pre-release. KISS is under active development. The source is MIT-licensed and buildable today — public binaries are coming soon.
shell
# Build and run from source
zig build run

# Run the full test suite
zig build test

# Install the service + tray (macOS / Linux / Windows)
./kiss --install
